"opencode-supabase": patch
---

Fix `/supabase` failing to load on recent OpenCode versions: the published package shipped raw TSX through `./tui`, and once the host stopped transforming TSX under `node_modules`, the import crashed on `react/jsx-dev-runtime` before the plugin could register.

Ship the rich `/supabase` TUI as compiled JavaScript (`dist/tui.js`) and rewrite `@opentui/core`, `@opentui/solid`, and `solid-js` imports at build time to canonical `opentui:runtime-module:*` IDs generated by OpenTUI's `runtimeModuleIdForSpecifier()`. Imports resolve to OpenCode's host-owned runtime modules, so the custom dialog renders without plugin-private OpenTUI/Solid copies (which threw `No renderer found` from a duplicate renderer context). Those packages are now optional peers and dev dependencies, not production dependencies.
